# 多轨编辑器播放重构方案（DAW transport）

> 状态：**待确认**（用户已确认设计决策，本文件为实施计划，确认后执行）
> 关联文档：`Docs/multitrack-editor-plan.md`、`Docs/changelog.md`

---

## 1. 目标

把多轨编辑器从「逐轨试听」升级为**标准 DAW 播放逻辑（transport）**：一个统一的播放/暂停控制，所有轨在同一音频时钟下同步播放，播放头在所有轨上同步跟随。

## 2. 已确认的设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | **统一 transport** | 一个 ▶/⏸ + 停止，所有轨同时起播/停止；不再每轨各播各的 |
| 2 | **标准 DAW 发声逻辑** | 每轨保留 `Mute` + `Solo` 两个独立开关；**默认都不勾 = 全部发声**；勾 Solo 则只听被 Solo 的轨；勾 Mute 该轨静音 |
| 3 | **播放复现编辑结果** | 播放即听到工程结果：全局选区裁切、淡入淡出、增益、Mute/Solo 全部实时生效 |
| 4 | **只播放高亮选区** | 有全局选区 → 只播该区间；无选区 → 播整曲。所有轨共用同一选区（现状已是全局选区，保持一致） |
| 5 | **附加功能** | 空格键播放/暂停、点击波形定位播放头、循环播放、保留每轨 ▶ 单轨试听 |

## 3. 技术方案

### 3.1 播放引擎（Web Audio）

必须用 Web Audio 而非多个 `<audio>` 元素——后者各元素独立解码时钟会逐渐漂移，无法满足「一起播放、播放头一致」。

- **解码与缓存**：首次播放时 `fetch('/api/mix/audio?path=…')` → `AudioContext.decodeAudioData()` → 按 `path` 缓存 `AudioBuffer`（与波形不同：波形走服务端 `/api/mix/peaks`，音频需前端解码）。
- **同步调度**：每轨按 `clips` 创建 `AudioBufferSourceNode`（`offset=clip.in`、`duration=clip.out-clip.in`），**全部使用同一个 `start(t0)`**（`t0 = ctx.currentTime + 0.05`）→ 样本级同步。
- **增益链**：`clip 淡变包络 → 轨增益 GainNode → （Mute/Solo 门控）→ masterGain → destination`。Mute/Solo 用 GainNode 值门控，**播放中切换即时生效，无需重启播放**。
- **裁切**：无 `clips` 的轨按整轨调度（offset 0、duration 整长）；有 `clips` 的轨按切片逐个调度到时间线位置。
- **播放头位置**：`pos = ctx.currentTime - t0 + startOffset`（用音频时钟，不用 `setTimeout` 计时，避免抖动）。

### 3.2 播放头渲染

- `requestAnimationFrame` 循环：每帧计算 `pos`，在所有轨的 canvas 上绘制一条竖线。
- 复用现有 `drawTrack()` 绘制管线（波形/压暗/选区已画完），播放头作为**最后一层**叠加绘制，避免整幅重绘开销。
- 停止/暂停时播放头停在当前位置；点波形可重新定位。

### 3.3 交互

| 操作 | 行为 |
|------|------|
| 单击波形（未拖动） | 定位播放头到该时间点 |
| 拖拽波形 | 选择全局区间（现有行为不变，所有轨一致） |
| 空格键 | 播放/暂停（焦点在输入框时不拦截） |
| 循环开关 | 开：在 `[sel0, sel1]` 循环（无选区则整曲循环）；关：播到末尾停止 |

区分「单击」与「拖拽」：`pointerdown` 记录位置，`pointerup` 时若位移 < 阈值视为单击（定位），否则视为选区。

### 3.4 UI 变化

- 母带行上方新增 **transport 行**：`▶/⏸`、`⏹`（停止回起点）、`循环` 开关、时间码 `mm:ss.d / mm:ss.d`。
- 每轨的 `Mute` / `Solo` 控件保留（默认不勾）。
- 每轨 `▶` 单轨试听按钮保留（试听原始整轨文件，与统一播放并存）。

## 5. 风险与取舍

1. **首次播放需下载并解码全部轨**：长曲（171s 立体声 WAV）约 30MB/轨，5 轨约 150MB 下载 + 内存中 float32 约 65MB/轨。首次播放有明显等待 → **必须显示「解码中 x/y」进度**，且解码结果缓存，后续播放即时。
2. **内存占用高**：Web Audio 不支持流式；超长曲（>10 分钟 × 多轨）内存压力大。缓解：仅在需要时解码、可考虑按需释放。
3. **循环 + 播放头**：用 lookahead 预调度（提前 ~0.5s 排下一轮 source）保证循环无缝；取消/重建需仔细清理已调度的 source，避免残留发声。
4. **与现有渲染（`/api/mix/render`）的关系**：播放是**前端实时预览**，渲染仍是后端 ffmpeg 离线产出最终文件；两者共用同一工程契约，需保证听感一致（倍数/量化差异允许）。

## 6. 分阶段实施

- **P1 播放引擎**：解码缓存 + 统一 transport + 增益/Mute/Solo/裁切/淡变（先做能同步播放）
- **P2 播放头与交互**：播放头渲染 + 点击定位 + 空格键
- **P3 循环与完善**：循环播放 + 时间码 + i18n + 测试 + 文档

每阶段完成后跑 `py_compile` + `pytest`，P1/P2/P3 完成后各做一次浏览器实测。
